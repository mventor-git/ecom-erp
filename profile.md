## 1. Project Overview
- Ecom start that organically grew into ERP; feature-rich but architecturally overgrown.
- Self-hosted MIT store + back-office + field apps; $0/month + provider fees.
- Direction: MODULAR MONOLITH recovery, NOT microservices, NOT rewrite.
- Preserve business logic/behavior; extract clean domain boundaries incrementally.
## 2. Vision
- Small merchant runs whole business from one deploy: catalog→orders→warehouse→delivery→books.
- Neutral core + swappable edges (locale, payments, vertical packs); setup wizard per deploy.
- Long-term: PostgreSQL backend, inventory as stock SSOT, explicit module interfaces, worker schedulers.
- Claim "fully" only after small-business accounting (invoices, AR/AP, cash-basis reports).
## 3. Target Users
- Merchants: 1–20 staff owners, non-technical, any retail vertical.
- Ops staff: stock/orders/invoices on admin panel. Field: pickers/packers/drivers via worker app.
- Contributors: module/locale/provider extenders. Future: suppliers via portal.
